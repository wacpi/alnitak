# 转码产物对齐分析：2028681619799281664

## 现象

该资源在播放器端「缺少约 300ms」的播放（总时长或结束位置偏短）。

## 分析结果

### 1. 源文件 vs 转码产物时长（ffprobe）

| 文件 | format.duration | stream.duration | stream.start_time |
|------|-----------------|-----------------|-------------------|
| upload.mov（源） | 710.997333 | 710.983333 / 710.997333 | **0.000000** |
| 1280x720_3004k_30_video.m4s | 711.033333 | 711.033333 | **0.100000** |
| audio.m4s | 711.018667 | 711.018667 | 0.000000 |

- 转码后视频/音频总时长略长于源（约 +36ms / +21ms），属正常误差。
- **问题 1**：视频流 **start_time=0.1s**。源为 0，转码后首帧 PTS 约为 0.1s，导致开头约 **100ms** 无有效画面（或播放器从 0.1s 起播，与「从 0 开始」预期不一致）。

### 2. sidx 解析（fragment 对齐）

对 `1280x720_3004k_30_video.m4s` 与 `audio.m4s` 解析 sidx 得到：

- **video**：timescale=15360，earliest_presentation_time=**0**（sidx 内为 0），ref_count=356，**total_duration_sec=711.033333**。
- **audio**：timescale=48000，earliest_pts=0，ref_count=355，total_duration_sec=711.018667。

sidx 内 fragment 总时长与 ffprobe 的 duration 一致，**末端未发现少 300ms**；即「缺 300ms」主要不在 sidx 总时长，而在**起始偏移**或**对外声明的总时长**。

### 3. 根本原因：MPD 总时长被截断（导致缺约 1 秒）

服务端生成 MPD 时使用：

```go
// video.go formatDuration
totalSeconds := int(seconds)   // 截断
return fmt.Sprintf("PT%dH%dM%dS", hours, minutes, secs)
```

- 当前资源：`TotalDuration = 710.997333`（来自源文件 ffprobe）→ `int(710.997333) = 710` → MPD 为 **PT11M50S = 710 秒**。
- 实际媒体：sidx 与 ffprobe 均为 **711.033s** 左右。
- 结果：播放器按 MPD 认为总时长为 **710s**，在 710s 处结束播放或触发结束事件，**实际内容还有约 1s（或你感知到的约 300ms～1s）未播完**。

因此「缺少约 300ms」更可能是：  
- 要么 MPD 截断导致少约 **1 秒**，你感受到的是其中一部分（例如 300ms）；  
- 要么叠加了**视频 start_time=0.1s** 带来的开头约 100ms 偏差。

## 结论与建议

| 问题 | 原因 | 建议 |
|------|------|------|
| 结束提前 / 缺一段 | **formatDuration 用 int(seconds) 截断**，MPD 比实际短约 1 秒 | 总时长改为四舍五入或带小数秒，见下 |
| 开头约 100ms 偏移 | 转码后视频 **start_time=0.1s**（源为 0） | 转码时用 setpts 或 output_ts_offset 使首帧 PTS=0（可选） |

### 建议修改（服务端）

1. **必须**：修正 `formatDuration`，避免截断导致 MPD 总时长短于实际。
   - 方案 A：四舍五入到整秒，例如 `totalSeconds := int(math.Round(seconds))`，使 710.997 → 711，MPD 为 PT11M51S。
   - 方案 B：保留小数秒，例如输出 `PT11M50.997S`（ISO 8601 支持），与 DB 中 TotalDuration 一致。

2. **可选**：若需「从 0 开始」的体验，在转码参数中让首帧 PTS 归零（如 ffmpeg setpts=PTS-STARTPTS 或 -output_ts_offset），减少开头 100ms 的偏差。

完成上述修改后，该资源（及同类长视频）的「缺 300ms/缺 1 秒」现象应可消除或明显缓解。
